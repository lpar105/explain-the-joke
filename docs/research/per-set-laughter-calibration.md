# Per-set laughter calibration from one labeled minute

Investigated 16 October 2026 for [Investigate calibration methods and evidence for improved laughter detection](https://github.com/lpar105/explain-the-joke/issues/31), under [Plan per-set laughter calibration from a manually annotated minute](https://github.com/lpar105/explain-the-joke/issues/30). This is research for the later human method/quality decision in [Choose calibration quality criteria and poor-sample behavior](https://github.com/lpar105/explain-the-joke/issues/34), not a production implementation or an accuracy benchmark.

## Answer and recommendation

One exhaustively labeled minute can fit a scalar decision threshold for this set. There is no evidence yet that this will detect audience laughter adequately outside that minute. Threshold fitting changes sensitivity; it cannot separate laughter from non-laughter when both have the same energy/ZCR score. A different representation may therefore be necessary, but that necessity must be established empirically.

**Recommended experiment:** retain the existing detector as the control, compare a directly fitted energy/ZCR threshold with a frozen pretrained laughter detector whose scalar threshold is fitted on the same minute, and evaluate both on disjoint, exhaustively labeled audio. Start with the smallest change as a diagnostic, not an assumption that it will ship. If it meets agreed held-out quality criteria, prefer its lower operational complexity; otherwise advance the semantic detector only if it passes those criteria. Do not fine-tune a neural network on one minute. Keep storage and manual annotation independent of the chosen detector.

All proposed procedures and expected failure modes below are hypotheses or deductions from code unless explicitly attributed to a published experiment. No app recordings, outside-sample annotations, model execution, runtime benchmark, or accuracy measurements were supplied or produced.

Protection must cover final normalized output, retries, and replacement, not only worker candidates. |

Code deductions, not measured app failures: loud speech, applause, music, or noise may score above quiet audience laughter. The score cannot distinguish equal-valued positive and negative frames. Later changes in gain, microphone position, or crowd/noise levels can invalidate a cutoff fitted earlier. A degenerate all-zero score has a zero default threshold and `>=` activation, so exact silence is an important explicit negative test.

## Alternatives and evidence

| Approach | What is learned from the minute | Practical assessment |
| --- | --- | --- |
| Current energy/ZCR control | Nothing | Already available; establish actual baseline error before claiming improvement. |
| Direct fitted energy/ZCR cutoff | One scalar cutoff, fixed extractor/segmentation | Cheapest feasible experiment. It tests whether score separation and sensitivity are sufficient in these recordings. Poor separation is a reason to change representation, not keep searching thresholds. |
| Frozen dedicated laughter detector | One scalar cutoff on pretrained frame scores | Preferred semantic challenger: designed for laughter and temporal segmentation. Adds weights and inference dependencies; audience mixtures and unseen rooms still need validation. |
| Frozen YAMNet class scores | One scalar cutoff on a predefined laughter-score aggregation | General sound-event challenger with a documented interface. Coarser temporal context makes boundary quality a material risk. |
| Frozen embeddings plus regularized classifier | A small supervised head, preferably global; per-set head is experimental | Represents more acoustic information than RMS/ZCR, but a high-dimensional per-set fit has far more degrees of freedom than this sample supports. Defer until scalar semantic scores prove inadequate and additional development data exists. |

The [Gillick et al. 2021 primary paper](https://www.isca-archive.org/interspeech_2021/gillick21_interspeech.html) reports degradation under real-world background noise and contributes precise laugh boundaries on AudioSet. It supports testing across conditions; its findings are not app accuracy. The [authors' implementation](https://github.com/jrgillick/laughter-detection) supplies Switchboard-trained weights and configurable frame threshold/minimum duration. It explicitly describes the lower-threshold false-positive/recall tradeoff and lists tested Python 3.6.1/PyTorch 1.3.1 versions. Validate modern Python 3.11 compatibility, dependency pins, weight provenance/license, and deployment cost before adoption.

[YAMNet's official documentation](https://github.com/tensorflow/models/blob/master/research/audioset/yamnet/README.md) specifies 521 class scores, 16 kHz mono audio, 0.96-second patches with 50% overlap, and 1024-dimensional embeddings. A 0.48-second output hop does not imply equally accurate event boundaries; interpolation cannot establish missing evidence. Define a score such as the maximum over an explicitly verified laughter class list globally, rather than choosing class combinations per minute. Scores from overlapping classes should not simply be summed as disjoint probabilities. The repository currently documents Keras 2 compatibility constraints. Its input features extend to 7500 Hz, so do not assume this app's 3200 Hz lowpass and denoising are appropriate model inputs. Test retained mono audio under the model's documented preparation first; compare a denoised variant separately.

The [official transfer-learning tutorial](https://www.tensorflow.org/tutorials/audio/transfer_learning_audio) demonstrates learning a classifier from frozen YAMNet embeddings. That establishes an implementation route, not sample sufficiency here. A minute yields roughly 125 overlapping YAMNet patches or 1500 correlated 40 ms frames, but potentially only a few independent Laugh Regions. A regularized head or positive/negative prototype may be worth a later ablation; neither is justified as superior by those frame counts.

The [AudioSet ontology](https://research.google.com/audioset/ontology/laughter_1.html) distinguishes laughter and subtypes; it does not identify the audience as the source. Generic detectors can flag the comic's own laughter. Define negatives as speech, performer-only laughter, applause/cheers, music, and room noise; where these overlap genuine audience laughter, the interval remains positive. Do not impose a hard speech/VAD veto that necessarily removes overlapping laughter.

For a current research direction, the [May 2026 MultiLinguahah preprint](https://arxiv.org/html/2605.06309v2) evaluates stand-up and other domains with source separation, energy proposals, BYOL-A representations, and Isolation Forest. It reports different rankings across languages/domains and evaluates both loose and strict temporal overlap. This reinforces the importance of domain and boundary evaluation. It is not evidence that unsupervised anomaly detection will work with one per-set minute. Its additional adaptation/separation stages make it a later alternative, rather than the first operational experiment.

## Minimal fitting experiment

1. Freeze media identity, preprocessing/extractor version, sample bounds, label revision, and segmentation policy. Use retained-set-relative timestamps. Extract full-set scores once, then select the sample portion; avoid sample-only filtering/padding changes. Model context crossing sample edges requires a documented alignment rule.
2. Use exhaustive manual intervals to define positive time and all remaining sample time as negative. Choose a fixed overlap rule for fitting frames; optionally exclude a predefined boundary uncertainty band from fitting only, retaining exact manual intervals in final output. Report excluded duration.
3. Search a deterministic bounded set of direct score cutoffs, including degenerate all-positive/all-negative diagnostics. Run the fixed production segmentation and normalization for each candidate, then clip predictions to the scored sample before computing the fit objective. Measure these raw automated predictions **before manual overlay**; evaluating overlaid manual labels would make sample-fit diagnostics trivially perfect. A duration-weighted F1 objective is a reasonable experimental default, but the method and quality decision must choose precision/recall costs and acceptable tradeoffs. Use a fixed tie-break, not additional hidden tuning.
4. Initially fit only this cutoff. Select gap, duration, smoothing, class aggregation, and any denoising variants on separate development recordings. Record positive/negative durations, independent event count, score overlap, sample-fit metrics, cutoff, versions, and explicit usability status. Threshold fitting is not probability calibration. The [scikit-learn threshold guide](https://scikit-learn.org/stable/modules/classification_threshold.html) separates score estimation from decision thresholds and warns about overfitting when fitting and threshold tuning reuse data.
5. Apply the frozen fitted result only to this set. A sample with both classes can still be uninformative: one weak event, near-constant scores, ambiguous labels, clipping, or unrepresentative sound conditions. Do not manufacture a statistically supported minimum event count from these sources. the method and quality decision must decide usability criteria; the approved flow has no unusable-sample bypass.

Manual authority is a requirement, not a fit metric: the [Decide calibration persistence and upload pipeline timing](https://github.com/lpar105/explain-the-joke/issues/33#issuecomment-6205872732) gates automatic analysis on saved Confirm Calibration and makes the entire sample authoritative. Remove every automated interval inside the sample, clip automation at its edges, and insert exact manual intervals. No downstream 0.2-second merge may fill manually negative time or alter manual endpoints. Assign each resulting Laugh Region to the Line where it begins once Lines exist. Preserve provenance, including seam fragments. A shorter set labeled in full has no automatic remainder and provides no independent within-set evaluation data.

## Evaluation outside the fitted minute

Collect representative sets with permission and exhaustive held-out annotations: multiple rooms/microphones, quiet and loud crowds, sparse laughs, speech/laughter overlap, applause, music, gain/noise changes, short laughs, and later portions of sets. Use the intended sample-selection workflow; selecting a favorable minute after inspecting errors biases the experiment. Obtain a second annotator on a subset to quantify boundary ambiguity.

Use development sets for method and global policy selection; reserve separate sets for the final comparison. Within every longer test set, the method may fit its required minute, but score only disjoint annotated remainder. Keep a context guard around the sample when evaluating pretrained windows/smoothing and exclude sample-crossing events from primary boundary statistics or report them separately. Split by set and preferably venue/session, never random adjacent frames. Full-file unsupervised processing is allowed for this offline workflow if fixed identically for all candidates; it must not consume held-out labels.

Compare current control, fitted energy/ZCR, fixed-threshold semantic detector, and per-set-fitted semantic detector on identical audio. The fixed semantic control distinguishes benefits of the representation from benefits of per-set fitting. Test denoising as a controlled variant, not an unreported preprocessing change.

Report paired per-set differences, both pooled and per-set summaries, and uncertainty resampled by set rather than correlated frames:

- Duration precision, recall, and F1 from interval intersections; accuracy alone is dominated by non-laughter.
- One-to-one event precision/recall, missed events, and spurious events per minute. Predeclare overlap matching, handling of splits/merges, and denominator conventions when there are no positives/predictions.
- Onset/offset absolute error and signed bias for matched events, plus loose/strict overlap results. Always show unmatched events separately so matching cannot hide boundary failures.
- Results by confound, room, laugh duration, and sparse-sample group; sample-fit versus held-out divergence.
- Worker latency, cold start, memory/CPU/GPU needs, failure rate, deployment compatibility, and cost per retained minute.

**Go/no-go:** before the final comparison, the method and quality decision must specify acceptable false positives, missed laughter, boundary errors, regression tolerances, and operational budget. Advance fitted energy/ZCR only if it passes on unseen remainder across required conditions. If it fails but the semantic challenger passes, change representation. If neither passes, stop adoption and investigate the failure categories rather than reporting calibration success from the fitted minute. Wide uncertainty or too few independent events means inconclusive evidence and more evaluation data, not a pass. Manual sample correctness remains mandatory regardless of detector performance.

## Questions sharpened for subsequent contracts

After the method and quality decision selects method and quality rules, define versioned calibration inputs/results, score-artifact retention, timestamp/window alignment, failure/usability status, and retry identity. Specify where final manual overlay occurs so normalization/retries cannot overwrite it; how manual and automated seam fragments retain provenance; and what intensity means for manually marked intervals without intensity labels. Changing media, preprocessing, sample, or labels invalidates fitted artifacts. These are contract questions; they do not reopen the confirmed upload commitment, playback handoff, or manual-authority decisions.
